# 技术面行情图渲染设计

## 决策

技术面报告采用双层图表输出：

1. 每份报告固定生成一张 Matplotlib 基准行情图；
2. 实际识别到的每个技术形态继续生成独立 Canvas 解释图。

这项决策以视觉完成度优先于此前“所有技术图均为 Canvas”的边界。基准图以 Base64 数据 URI 内嵌到 `technical_report.html`，因此导出文件不依赖 API、磁盘图片路径、CDN 或网络，但文件内会包含 PNG 数据。

## 基准行情图

### 位置与数据

- 固定置于“二、趋势分析”之后，即使未识别任何形态也必须存在；
- 使用当前 run 的 `market_data.csv` 和 `technical_indicators.json`；
- 默认展示最近 180 个交易日；
- 图像由受信 Python 节点确定性生成，不读取 Agent 文本，也不使用预测或外部资料。

### 视觉和信息结构

延续用户提供样图的专业行情图构图：

- 白色画布、细灰外框、黑色坐标轴和低透明度网格；
- 上方主区约占 72%，展示收盘价、SMA5、SMA20、SMA60、20/60 日支撑位、20/60 日阻力位；
- 下方成交量区约占 28%，展示成交量柱及 20 日均量；
- 图内左上角使用紧凑多列图例，按价格、均线、支撑阻力分组；
- 时间轴按月或自动稀疏刻度显示，标签旋转约 30 度；
- 线型和颜色语义固定：价格蓝色、短/中均线橙/绿、长均线红、支撑绿色虚线、阻力红色虚线、成交量灰蓝、均量橙色；
- 标题为“{symbol} Technical Chart”，保证完整报告与原始图一致的识别习惯。

### 生命周期与兼容

- `technical_chart.png` 重新成为技术研究节点的必备产物；
- 报告生成时读取图片、Base64 内嵌，不暴露外部 `/artifacts/` 图片 URL；
- 恢复、重建和 Manifest 校验将把该文件纳入技术图依赖；
- 旧 run 没有图片时，从技术研究节点重建，不对缺图报告静默降级。

## Canvas 形态解释图

Canvas 不再承担“替代完整行情图”的角色，而是仅用于紧贴形态段落的解释。每张形态图仍有价格—成交量骨架，MACD/RSI 按需增加指标区，并在图内展示对应形态说明。

### 渲染样式说明

每张 `ChartSpec` 生成时携带以下确定性样式说明，供 Canvas 渲染器统一执行；这不是模型 Prompt，也不会改变数据或研究结论：

```text
机构技术图风格：白色图底、黑灰坐标轴、浅灰网格；价格主区优先，
成交量和指标区次之。X 轴最多显示 6 个等间隔日期，必要时使用月度
短标签；Y 轴每个分区最多 4 个刻度。图例只保留当前读图所需的核心
序列，并避免与形态标注重叠。形态标注使用一条细引线、一个低饱和
紫蓝色标签和简短名称；不叠加多个无关形态，不制造密集的垂直辅助线。
价格、均线、支撑阻力、成交量与均量的颜色在所有技术图中保持一致。
```

### 可读性规则

- 形态信号只标记当前图对应的一个 `PatternSignal`；
- 价格图与成交量图共享时间范围和横轴；
- MACD、RSI 图在保留价格—成交量骨架的前提下增加专属指标区；
- 指标区、成交量区均不与主图区抢占同等高度；
- 长日期、过多刻度、完整值列表都不直接绘制到图面；详情由悬浮提示与图下“触发、确认、失效”规则承接；
- 图片或单张 Canvas 图生成失败时，不中断正文：基准图缺失为技术报告校验失败，单形态图失败则保留文字说明。

## 测试与验收

- 技术研究节点生成 `technical_chart.png`，并通过最小文件与可读取性校验；
- HTML 导出包含内嵌 `data:image/png;base64,` 基准图，不包含外部图片 URL；
- 基准图包含 180 日价格、均线、支撑阻力、成交量与均量；
- Canvas 样式配置存在，且技术图 X 轴不超过 6 个标签、单分区 Y 轴不超过 4 个刻度；
- 无形态任务仍输出基准图；每一个形态保持一图一标注；
- 现有报告安全边界、离线导出和技术面工作流恢复测试保持有效。

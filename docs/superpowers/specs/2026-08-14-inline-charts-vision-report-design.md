# 形态就地图表、比较型制图与 Vision 研报设计规格

## 目标

本次改造同时解决四个问题：

1. 技术面图表集中堆叠，形态与图形脱节；
2. 基本面图表规划偏向“能画就画”，缺少变化或比较判断；
3. 导出 HTML 后图表可能不显示；
4. 报告与图表视觉过于朴素，缺少 iOS 原生质感和设计层次。

最终视觉采用用户确认的 **C1 Institutional Vision**：以机构研报的连续阅读结构为主体，使用 iOS / visionOS 风格的半透明材质、环境光、圆角、细边框和克制阴影增强层次，但不做 Dashboard 卡片墙。

## 一、技术面：一个形态一张图，并在形态处说明

### 图表生成

`build_technical_visuals` 不再按 `chart_family` 合并信号，而是按每个 `PatternSignal` 生成独立 `ChartSpec`。

每张图：

- 只对应一个实际识别形态；
- 只包含该形态的 Annotation；
- 标题包含形态名称；
- 图内标出识别位置；
- 图下展示触发、确认、失效条件；
- 继续使用该形态所属指标族需要的行情和指标序列。

同一指标族识别出多个形态时，各生成一张图。图表 ID 使用指标族、形态安全标识和序号组成，避免冲突。

### HTML 位置

删除报告顶部统一的“技术形态图表”区域。

“技术形态候选”章节按实际形态生成以下连续结构：

```text
形态名称与判断
→ 当前形态专属图表
→ 图内识别标记
→ 触发 / 确认 / 失效说明
→ 数据来源
```

没有对应结构化 `PatternSignal` 的观察项只保留文字。某一形态图生成失败时，只在该形态位置显示轻量提示，不影响其他形态和报告后续章节。

## 二、基本面：只有存在比较价值才规划图表

### Writer Planning 规则

`visual_plan` 允许为空，不设置最少图表数。

Writer Planning 只有在材料能够形成下列至少一种关系时才规划图表：

- 时间变化：同一指标跨两个及以上可比期间；
- 横向比较：同一口径下公司、同行或行业之间的比较；
- 情景对照：同一指标在不同情景或假设下的比较；
- 结构变化：业务、产品、地区或成本构成的可比结构。

每个 `PlannedVisual` 增加：

- `comparison_mode`：`time_series / cross_section / scenario / composition`；
- `comparison_basis`：说明比较对象、统一口径以及图表要回答的问题。

不得为以下内容制图：

- 单个孤立数字；
- 只有一个期间或一个对象的数据；
- 单位或定义不一致的数据；
- 仅为了装饰页面的数据；
- PE、PB、PS、DCF 每股价值等不同含义或单位的混合柱状图。

估值快照继续使用数据表或指标组件。只有未来具备同一估值方法的历史、同行或情景数据时，才允许生成估值比较图。

### 确定性校验

图表插件在生成后校验：

- 至少两个标签或比较对象；
- 至少一个序列包含两个可用数据点；
- 数据单位统一；
- `comparison_mode` 与数据形状相符；
- Evidence 图表的每个数值仍能在授权 Evidence 中逐点核验。

校验不通过时将图表标记为 `skipped`，说明原因，但不中断报告。

## 三、图表组件与坐标轴

所有图表使用统一 CSS 组件结构：

```text
chart-component
├─ chart-header：编号、标题、单位
├─ chart-legend：统一图例
├─ chart-stage：坐标轴、网格和绘图区
├─ chart-explanation：图表结论
├─ chart-rules：技术形态触发/确认/失效
└─ chart-source：来源与口径
```

绘图运行时补齐：

- 主纵轴数值刻度；
- 存在第二单位时的右侧纵轴；
- 横轴刻度抽样和边界避让；
- 零轴、负值和柱状图基线；
- 浅色网格线；
- 单位标签；
- 系列图例；
- 当前形态标记及说明；
- 高 DPI 画布；
- 窗口变化后的重绘；
- iOS 材质 Tooltip。

颜色保持统一含义：核心公司或主序列使用系统蓝，辅助序列使用石墨灰和低饱和紫；正负向颜色只在确有数据含义时使用。

## 四、C1 Institutional Vision 整体排版

### 页面材质

- 背景使用低饱和蓝、紫、青环境光，不使用高饱和营销渐变；
- 报告主体使用半透明白色材质、`backdrop-filter` 和细白边；
- 不支持模糊的浏览器自动回退为高透明度白色；
- 主报告仍保持 1160px 左右的机构研报阅读宽度；
- 系统字体优先使用 SF Pro / PingFang SC / Segoe UI；
- 数字使用等宽数字特性。

### CSS 组件

新增或统一以下组件：

- `report-surface`：报告主材质；
- `report-hero`：标题、公司、日期和报告属性；
- `summary-material`：摘要与核心判断；
- `metric-strip`：少量关键指标，不形成卡片墙；
- `thematic-section`：连续专题章节；
- `chart-component`：统一图表容器；
- `signal-rules`：触发、确认、失效；
- `observation-material`：观察点和优化建议；
- `evidence-drawer`：来源索引。

玻璃材质用于建立层级，不给每个段落单独加卡片。正文保持 15.5–16px、1.75–1.8 行高和清晰标题层级。

### 打印

`@media print` 中：

- 去除环境光、模糊、透明和阴影；
- 使用纯白背景和深色正文；
- 保留图表坐标轴、图例、说明和来源；
- 图表与形态说明避免分页切断；
- 标题避免孤立在页尾；
- 表格不横向溢出。

## 五、导出后图表不消失

### 导出路径

技术面和基本面统一直接导出当前 Run 已生成且已校验的完整 HTML Artifact：

- `technical_report.html`
- `fundamental_report.html`

不再用经过 Bleach 截取的页面片段二次包裹技术面报告。导出前校验文件必须位于当前 Run Artifact 目录且文件名符合分析类型。

### 自包含要求

导出 HTML 必须包含：

- 内联报告 CSS；
- 内联 `data-report-visuals`；
- 内联图表运行时；
- 原生 Canvas 和 HTML/CSS 图表组件；
- 不依赖 `/static/`、CDN、外部字体、PNG 或 SVG。

图表运行时在 DOM 可用后通过 `requestAnimationFrame` 首次绘制，避免文件刚打开时容器宽度尚未稳定导致空白；同时保留 resize 重绘。

### 失败边界

若某图缺少数据或绘制失败：

- 保留标题、图例、说明和来源；
- 显示“当前图表数据不可用”的局部提示；
- 不影响其他图表和正文；
- 不把整个报告标记为失败。

## 六、测试与验收

### 技术面

- 两个同族形态生成两张图；
- 每张图只有一个对应 Annotation；
- 图表出现在对应形态章节，不再出现在报告顶部；
- 每张图包含触发、确认和失效说明；
- 单图失败不影响报告。

### 基本面

- 空 `visual_plan` 合法；
- 单点、单位不一致或无比较声明的图表被跳过；
- 时间、横向、情景和结构比较可以生成；
- 混合估值快照不再制图；
- 图表跳过不影响 Writer 和最终报告。

### 导出与视觉

- 两类导出均直接返回完整自包含 HTML；
- 导出文件包含图表数据、Canvas、内联运行时和内联 CSS；
- 导出文件不含 `/static/`、CDN、PNG 或 SVG；
- 报告页面包含 C1 Vision CSS 组件；
- Canvas 运行时包含左右坐标轴、刻度、单位、图例和延迟首绘；
- 打印样式会关闭玻璃材质并保留图表来源。

## 非目标

- 不引入 ECharts、Chart.js 或其他外部依赖；
- 不生成 PNG、SVG 或服务端截图；
- 不改变技术指标、财务指标、估值和 Evidence 权威边界；
- 不因为图表失败阻断报告；
- 不把研报改造成行情 Dashboard。
